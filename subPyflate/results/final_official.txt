Speedup: **1.586x** (120.99 / 76.307)
Improvement: **36.93 %** (well above the >= 7 % target -- ~5x margin)

Interpretation:
- All indicators of "less work done" drop by roughly a THIRD: instructions
  retired -32.87 %, branches -33.51 %, branch-misses -37.82 %.
- Wall-clock time drops by more (-36.93 %) than pure instruction count
  (-32.87 %) - the remaining instructions also have better temporal
  locality (branch-misses fall harder than branches, cache references drop
  -24.53 %).
- cache-misses is essentially flat: the workload's working set was already
  small enough to fit in cache; the optimization removed interpreter work
  rather than memory traffic. Cache-miss RATE went up (4.09 % -> 6.93 %)
  purely because the RATIO shifts when the numerator stays roughly the
  same but references drop. Absolute misses are unchanged.
- page-faults and context-switches are basically flat, showing the
  optimization is CPU work, not memory allocation or OS scheduling.
