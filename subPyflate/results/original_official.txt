Interpretation:
- `_PyEval_EvalFrameDefault` dominates - every Python opcode passes through it.
- `list_dealloc` and `list_ass_slice` appear high, both driven by the
  original `move_to_front` slice pattern (three list allocations per symbol).
- Debug-allocator overhead (`_PyMem_DebugCheckAddress`) is inherent to
  python3-dbg and would disappear under release CPython.
- `cycles` shows 0 because the specific cycles PMU event isn't exposed by
  the current KVM PMU config on this Xeon host. All other hardware counters
  (instructions, branches, branch-misses, cache-references, cache-misses)
  ARE exposed and captured cleanly - see the numbers above.

Hardware counters status:
- Available: instructions, branches, branch-misses, cache-references, cache-misses
- Not available: cycles (KVM host-specific PMU limitation)
- Software counters: task-clock, cpu-clock, page-faults, context-switches all captured
