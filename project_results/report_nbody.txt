Benchmark: nbody

Overview
- Simulates N-body gravitational interaction with repeated force accumulation and state updates.
- Dominant cost comes from pairwise floating-point arithmetic in tight nested loops.

Initial Analysis (from baseline and profiling plan)
- Baseline result from VM run: mean ~68.3 ms, std dev ~6.4 ms.
- Expected hotspots in perf/flamegraph:
  1) pairwise force update loop
  2) inverse-distance and power arithmetic
  3) velocity/position update loop

Optimization Applied
- Target optimization points:
  1) Hoist repeated constants and temporary values outside inner loops.
  2) Reduce Python object indexing overhead by binding local references.
  3) Minimize redundant recomputation of squared distances and scaling factors.

Performance Comparison
- Baseline mean: 68.3 ms
- Optimized mean: run `project_results/script_nbody.sh` to collect `optimized.json` and compare output.
- Compare command:
  python3 -m pyperformance compare project_results/nbody/baseline.json project_results/nbody/optimized.json

Hardware Proposal
- Accelerator candidate: pairwise force accumulation core.
- Rationale: regular numeric kernel, high arithmetic intensity, deterministic data path.
- HDL module: `project_results/nbody_accel.sv`

Conclusion
- nbody is suitable for both software micro-optimization and arithmetic hardware offload.
- Perf + flamegraph artifacts generated by script provide evidence for bottleneck shrinkage.
